# AI 工作约定：SVG 绘图组件

## 作用与边界

本目录是网站设计项目中的 SVG 绘图组件，供 AI 创建、修改和检查 logo、图标、插画等 SVG 素材。交付物是可编辑的 SVG 文件；需要时另行交付 PNG。

网站主项目负责页面、布局、交互及素材接入。本组件负责素材本身及其视觉检查，使用现有 `svg` 命令生成预览，不要求网站采用特定框架，也不需要开发服务器或构建步骤。Node.js 和渲染依赖用于制作阶段。

- 以用户当前任务和主项目提供的设计要求为准，只处理本次指定的素材及相关文件。
- 仓库中的既有院徽、logo 和参考图是具体设计素材，不是所有网站项目必须沿用的主题或默认交付物。
- 嵌入其他仓库后，遵守适用的上级项目约定。本文件所称“组件根目录”指包含本文件、`svg` 和 `package.json` 的目录，不一定是网站仓库根目录。
- 本规则表达组件内的操作授权；实际读写能力仍以宿主应用和沙箱权限为准，不授予组件目录外的写入权限。

## 必须执行的工作流程

1. 读取本次目标 SVG、相关参考素材和设计要求，确定用途、尺寸、颜色及保存位置；可从已有信息确定的内容无需重复询问。
2. 直接创建或修改正式 SVG，保留可编辑的矢量结构。正式文件放在 `.tmp/` 外，沿用主项目指定的素材目录或现有存放位置。
3. 在组件根目录执行 `./svg render "目标.svg"`；需要更大预览时加 `--width 1600`。仅在缺少依赖时执行 `npm ci`，环境要求为 Node.js 18 或更新版本。
4. 将命令输出的 PNG **绝对路径**传给图片查看工具（如 `view_image`），实际读取画面，检查轮廓、比例、颜色、对齐、裁切及文字效果。渲染成功只表示文件可被渲染，不能据此声称视觉效果正确。
5. 按检查结果修改；每次修改后重新渲染，并查看最终版本。若无法渲染或查看，应明确说明尚未完成的检查。
6. 保留正式 SVG；如需交付 PNG，先将预览复制到 `.tmp/` 外的正式目录。清理临时文件后，告知交付路径和检查结果。

命令、路径及网站接入说明见 [SVG工作流声明.md](SVG工作流声明.md)。

## 素材与文件管理

- 默认保留用户原始素材和参考图；不因清理或打包而删除它们。
- SVG 尽量自包含：图形使用矢量元素；确需引用位图时使用内嵌 data URL，避免依赖当前机器的文件路径。
- 渲染器加载系统字体。需跨环境稳定显示的文字可转为路径；保留仍需编辑的文字源文件，不将本机字体效果视为其他环境的保证。
- 所有可丢弃的中间 SVG、预览图、测试素材和其他临时文件统一放在组件根目录 `.tmp/`，不在其他目录散落临时文件。
- 同一源 SVG 的预览自动覆盖，无需为每次修改建立新预览文件。
- AI 已获授权随时执行 `./svg clean`，清空组件 `.tmp/` 中的全部内容，无需另行确认；因此 `.tmp/` 不得存放唯一原件或正式交付物。
- 任务结束前清理临时文件。不将 `node_modules/` 或 `.tmp/` 纳入版本控制。
